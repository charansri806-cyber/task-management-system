# TaskFlow deliverable outcomes

- [x] **Dashboard and task overview** — Displays Total Tasks, Completed Tasks, Pending Tasks, High-Priority Tasks, and Task Completion Percentage. Statistics update automatically after task creation, editing, deletion, and completion changes. Each task shows its title, description, creation date, due date, priority, and current status in an organized layout.
- [x] **Create and validate tasks** — Provides fields for Task Title, Task Description, Due Date, Priority (High, Medium, Low), and Task Status (Pending or Completed), plus an Add Task button. Validates inputs and prevents empty task submissions and invalid/incomplete stored data.
- [x] **Edit and delete tasks** — Allows users to update title, description, due date, priority, and status; saves and reflects changes immediately. Allows task deletion only after displaying a confirmation message.
- [x] **Toggle completion** — Provides a checkbox; completing a task updates its status, visually distinguishes it from pending tasks, updates dashboard statistics, and allows the user to mark it pending again.
- [x] **Search, filters, and sorting** — Searches tasks by title. Filters by All Tasks, Completed Tasks, Pending Tasks, High Priority, Medium Priority, and Low Priority. Sorts by Newest First, Oldest First, Due Date, and Priority.
- [x] **Responsive professional interface** — Provides a professional light theme with statistic cards, clean typography, spacing/alignment, rounded corners, subtle shadows, hover effects, professional buttons, navigation, responsive task cards, and reduced-motion support. Responsive styles were captured and inspected at a 390-pixel mobile viewport; the layout also includes tablet and desktop breakpoints.
- [x] **REST API and persistent backend** — Uses Node.js and Express.js with GET `/api/tasks`, GET `/api/tasks/:id`, POST `/api/tasks`, PUT `/api/tasks/:id`, PATCH `/api/tasks/:id/complete`, and DELETE `/api/tasks/:id`. Uses proper HTTP methods, input validation, error handling, JSON responses, unique task IDs, and persistent JSON-file storage. API CRUD, status reversal, invalid inputs, not-found responses, file persistence, and survival after a Node server restart were exercised; test data was removed.
- [x] **Project documentation and GitHub preparation** — Includes README project description, technologies, features, installation instructions, how to run, API documentation, project folder structure, and a screenshots section with instructions for adding screenshots. Includes `.gitignore`; no passwords or API keys are included. GitHub push status is described accurately.
- [x] **Windows execution and presentation guide** — README includes step-by-step required software installation, opening the folder in VS Code, installing dependencies in PowerShell, running the application with `npm start`, opening `http://localhost:3000`, troubleshooting, and a faculty demonstration script.
- [x] **Functional quality** — The finished project is a complete working application; all visible controls are wired to intended actions; frontend is connected to backend APIs; code is organized, readable, beginner-friendly, and uses one runtime dependency. JavaScript syntax, JSON files, CRUD, status reversal, invalid input handling, persistence through refresh/restart, and mobile layout were checked; temporary test data was cleaned up.
